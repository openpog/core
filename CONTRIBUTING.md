# Contributing to Open Publication Origin Gateway

Thank you for your interest in contributing to the Open Publication Origin Gateway specification.
This document outlines how to contribute to this project.

## Specification Proposal Guidelines

### Principles of OpenPOG

1. **Simple + Minimal**: It is much easier to add things to a specification than it is to
   remove them. To maintain simplicity, we keep a high bar for adding new concepts and
   primitives as each addition requires maintenance and compatibility consideration.
2. **Concrete**: Specification changes need to be based on specific implementation
   challenges and not on speculative ideas.

### Stages of a specification proposal

1. **Define**: Explore the problem space, validate that other POG users face a similar
   issue, and then clearly define the problem.
2. **Prototype**: Build an example solution to the problem and demonstrate its practical
   application.
3. **Write**: Based on the prototype, write a specification proposal.

## Submitting Changes

1. Push your changes to your fork
2. Submit a pull request to the main repository
3. Follow the pull request template
4. Wait for review

## AI-Assisted Contributions

Open Publication Origin Gateway welcomes AI-assisted contributions from the community.

Our position is straightforward: AI usage is acceptable, including for substantial drafting or implementation work,
as long as the submission adds clear, real value to the project and meets the same quality bar as any other contribution.

Disclosure: The original author uses AI tools as part of the design and drafting process for these specifications.

### Evaluation criteria

AI-assisted contributions are evaluated on the same standards as all other submissions:

- **Substantive value** - The change materially improves the specification or project artifacts
- **Technical and editorial quality** - The contribution is accurate, coherent, and maintainable
- **Contributor understanding** - The submitter can explain the change and its implications
- **Evidence and rationale** - The PR includes clear reasoning, examples, or supporting validation where relevant

Submissions may be closed when they do not provide meaningful value or do not meet project quality standards.
